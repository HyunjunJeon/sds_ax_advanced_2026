# Jev와 System One 모델

Jev는 TypeSafe AI가 공개한 첫 System One 모델이다. 일반 LLM과 달리 **텍스트를 생성하지 않는다**. 상태(state)와 타입이 정해진 질문(questions)을 받으면, 소프트웨어가 바로 쓸 수 있는 구조화 답과 확률을 돌려준다.

LangChain 블로그 *Building a Harness with Jev*는 이 점을 에이전트 루프에 연결한다. 에이전트는 매 결정마다 비싼 채팅 모델을 부를 필요가 없다. 분류·라우팅·가드레일처럼 "예/아니오, 어느 쪽, 몇 점인가"로 끝나는 판단은 Jev에 맡기고, 열린 추론과 문장 생성만 LLM에 남긴다.

## 세 가지 질문 타입

| 타입 | 하는 일 | 반환 |
| --- | --- | --- |
| Noul | 참/거짓 판단 | `noul` 확률 (0–1) |
| Choice | 닫힌 선택지 중 하나 | `choice`, `probabilities`, `confidence` |
| Score | 순서가 있는 척도 | `score`, `probabilities`, `confidence` |

한 요청에 여러 질문을 넣으면 Jev는 이를 **병렬**로 평가한다. 질문을 추가해도 응답 시간은 거의 늘지 않고, 비용은 추가 질문 토큰 정도다.

## 에이전트 하네스에서의 쓰임

1. **모델 라우팅**: 단순 조회는 싼 모델, 아키텍처·고위험 결정은 강한 모델.
2. **Auto Mode**: `bash`나 게시처럼 부작용이 있는 도구 호출을 실행 전에 위험 확률로 차단.
3. **RAG 게이트**: 검색된 패시지가 관련 있는지, 근거인지, 질문의 전제를 뒤집는지, 프롬프트 주입인지.

Jev는 LLM을 대체하지 않는다. 생성은 LLM, 구조화된 판단은 Jev — 이 분업이 하네스다.

회사는 분류 작업에서 비슷한 LLM 대비 최대 200배 빠른 추론과 400배 낮은 비용을 보고했다. 수치는 벤치마크와 워크로드에 따라 달라진다.
