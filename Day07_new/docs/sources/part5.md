# Part 5 근거 대장

Part 5(Local Model과 Agent 연결)에서 노트북이 인용할 사실만 모은 대장이다.

- 약칭: `V` = vLLM v0.32.0 소스(커밋 5df63a7), `VD` = 같은 소스 트리의 `docs/`(공식 문서 원문), `LC` = `.venv/lib/python3.13/site-packages/langchain_openai/chat_models/base.py`(langchain-openai 1.7.3), `DA` = `.venv/lib/python3.13/site-packages/deepagents/graph.py`(deepagents 0.7.32), `DS` = 같은 패키지의 `deepagents/middleware/summarization.py`, `T` = `zai-org/GLM-5.3-Flash`의 `chat_template.jinja`(revision `46a050bec13002ad29ee795c16e61cf4fa3c4a9c`, sha256은 `Day07_new/data/reference_parser_stream.json`의 `tokenizer.files_sha256`). Pod가 쓰는 체크포인트 revision은 확인하지 못했다.
- 블로그는 절 제목으로만 가리킨다. 블로그 절 5 = "5. 멀티턴 대화: prefix caching을 통한 이전 턴 KV 재사용".
- 상태: 일치, 문서·코드 차이, 블로그·코드 차이, 코드 전용, 미확인 중 하나.
- 이 대장에 쓴 "실측"은 가짜 서버(httpx MockTransport)로 `ChatOpenAI`와 `create_deep_agent`를 돌려 요청 본문을 본 것이다. 네트워크와 유료 호출은 없었고 스크립트는 저장하지 않았다. "렌더링 실측"은 위 `T`와 같은 revision의 진짜 tokenizer로 사람이 만든 대화를 `apply_chat_template`에 넣어 token열을 비교한 것이다. 서버, 엔진, 모델 출력은 없다.
- `V` 행은 Python frontend 경로다. 레시피 기본 명령의 Rust frontend 렌더링은 이 대장에서 읽지 않았다(P6-28, P6-35).

### ChatOpenAI (`.venv/lib/python3.13/site-packages/langchain_openai/chat_models/base.py`, langchain-openai 1.7.3)

- 모듈 독스트링이 직접 말한다. 공식 OpenAI 스펙만 대상으로 하고, 제3자가 추가한 비표준 응답 필드(`reasoning_content` 등)는 추출·보존하지 않으며, vLLM을 가리킬 때는 provider 전용 패키지를 쓰라고 안내한다(`base.py:5-10`, 클래스 독스트링 `base.py:787-791`).
- 실측: 비스트리밍과 스트리밍 모두 응답 `reasoning`이 `AIMessage.additional_kwargs`에 없다. 그래서 `Day07/README.md:68`은 맞다. 사고 과정은 openai SDK로 본다는 `Day07/runpod_openai_reasoning.py:3-4`의 방침도 유효하다.
- `extra_body`는 요청 JSON 최상위로 합쳐진다(`base.py:1146`, `base.py:1572`). Day07의 `chat_template_kwargs`가 vLLM 필드와 같은 위치에 실린다.
- 사용량: 응답의 `prompt_tokens_details.cached_tokens`를 `usage_metadata["input_token_details"]["cache_read"]`로 옮긴다(`base.py:4503-4508`). 스트리밍은 `base_url`을 지정하면 `stream_usage`가 켜지지 않아 `stream_options`가 요청에 실리지 않는다(`base.py:1431-1450`, `base.py:1844-1862`, 실측). 켜려면 `stream_usage=True`를 명시한다. 비스트리밍 `invoke`에서는 usage가 응답에 있으면 바로 들어온다(실측).
- 다음 턴 요청의 assistant 메시지에는 `content, role, tool_calls`만 실린다. `reasoning`은 실리지 않는다(실측). GLM-5.3-Flash 템플릿은 그 자리를 빈 생각으로 렌더링하므로 앞 턴 답변 구간의 block은 재사용되지 않는다(P5-22).

### create_deep_agent (`.venv/lib/python3.13/site-packages/deepagents/graph.py`, deepagents 0.7.32)

- `model`에 `BaseChatModel` 객체를 주면 그대로 쓴다(`graph.py:289-293`, `graph.py:628`, `graph.py:648`). `ChatOpenAI(base_url=..., extra_body=...)`를 넘기면 그 설정대로 요청이 나간다.
- system prompt는 `USER → BASE → SUFFIX` 순으로 조립되고, `system_prompt=None`이며 profile에 내용이 없으면 서버가 받는 system 메시지는 빈 문자열이다(`graph.py:363-374`, `graph.py:673-682`). 실측으로도 빈 문자열이었다.
- 도구 사용 안내문은 기본으로 넣지 않는다(`graph.py:684-691`). 실측 도구 목록: `ls, read_file, write_file, edit_file, delete, glob, grep, task`.
- 캐시 middleware 중 Anthropic·Bedrock·Fireworks 것은 해당 모델이 아니면 아무것도 하지 않는다(`graph.py:407-413`). vLLM의 서버 쪽 prefix cache는 이 middleware와 무관하게 동작한다.
- 안정성 실측: 한 프로세스 안의 두 번 호출, 별도 프로세스 두 번 모두에서 system 메시지와 tools JSON의 SHA-256이 같았다. 도구 순서도 같았다. 2번째 요청의 앞 두 메시지(system, user)는 1번째 요청과 같다. 그러나 긴 실행에서는 `write_file`·`edit_file` 인자 줄이기가 앞쪽 assistant 메시지를 바꾼다(P5-21). 요약 발동과 skills·memory 변동은 실행하지 않았다.

## 수업에 쓰지 말 것

- "`ChatOpenAI`가 reasoning을 버린다"를 vLLM 버그처럼 말하지 않는다. 클라이언트가 표준 필드만 읽는 설계다(`base.py:5-10`).
- "응답 필드는 `reasoning_content`다"라고 쓰지 않는다. v0.32.0은 `reasoning`이다(P5-15). Pod 이미지의 실제 이름은 확인 전까지 단정하지 않는다.
- "Pod에서 cached_tokens를 바로 볼 수 있다"고 쓰지 않는다. 서버 플래그 `--enable-prompt-tokens-details`가 켜져 있어야 하고(P5-11), 스트리밍은 `stream_options.include_usage`도 필요하다(P5-12). Day07 문서에는 이 플래그 기록이 없다.
- `clear_thinking`을 vLLM 서버 옵션으로 설명하지 않는다. vLLM 소스에는 없고 체크포인트 템플릿의 변수다(P5-14). Pod의 템플릿 revision은 확인 전까지 단정하지 않는다.
- "effort를 max에서 low로 바꿔도 캐시가 유지된다"고 쓰지 않는다. 템플릿 렌더링에서 첫 block부터 갈라진다(P5-13). 다만 렌더링 비교이고 서버의 `cached_tokens` 측정은 아니다.
- tool 순서가 바뀌어도 서버가 정렬해 주므로 괜찮다고 말하지 않는다. Python frontend는 요청 순서 그대로 넘긴다(P5-08).
- "system prompt를 바꾸면 전체 prefix가 사라진다"고 쓰지 않는다. 달라진 token 앞의 block은 재사용되고, GLM-5.3-Flash 템플릿에서 system은 tool 정의 뒤에 온다(P5-08).
- "앞 턴 답변의 KV도 대부분 재사용된다"를 `ChatOpenAI`와 GLM-5.3-Flash 경로에 그대로 말하지 않는다. 그 경로는 앞 턴 prompt까지다(P5-22).
- "system과 tools 해시가 같으니 prefix가 안정적이다"로 끝내지 않는다. 긴 실행에서 messages가 바뀐다(P5-21).
- "vLLM에는 세션이 전혀 없다"고 단정하지 않는다. `session_id` 필드가 있으나 캐시와는 무관하다(P5-02).
- "RunPod 100초 제한" 수치를 vLLM의 동작처럼 쓰지 않는다. 강사 검증 메모이며 이 대장에서는 미확인이다(P5-24).
- deepagents의 prompt caching middleware를 vLLM 서버 캐시로 소개하지 않는다(P5-25).
- 블로그 문장을 그대로 옮기지 않는다. 설명은 이 대장의 `파일:줄`로 다시 확인한 뒤 자기 말로 쓴다.
