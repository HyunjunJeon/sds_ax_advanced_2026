# Part 1 근거 대장

vLLM 서빙 기초(step, 컴포넌트, 서버 초기화, request 경로, 상태, 기본 실행 경로, Rust frontend)에 대해 수업이 인용할 사실만 모은 대장이다.

## 읽는 법

- 기준 소스는 vLLM v0.32.0(커밋 `5df63a7`, 2026-10-17)이다. 코드 열의 `vllm/...:줄`과 `rust/...:줄`은 그 소스 루트 기준이다. 각 줄을 열어 주장과 맞는지 확인했다.
- 블로그는 절 제목으로만 가리킨다(Inside vLLM, 큰 그림 / 서버 초기화 / request 처리 / 소개). 문장은 옮기지 않았다.
- 공식 문서 열의 `docs/...`는 v0.32.0 소스 트리 안의 문서다. `이슈 #n`, `PR #n`은 `gh`로 읽은 GitHub 본문이다. 온라인 docs.vllm.ai 페이지는 열어 보지 않았다. 레시피는 GLM-5.3-Flash 레시피 페이지(2026-10-19 갱신본)다.
- 코드는 읽기만 했고 실행하지 않았다. "동작한다"가 아니라 "코드에 이렇게 적혀 있다"로 읽을 것. 2026-11-02에 모든 행을 원문과 호출 경로로 다시 대조해 조건과 판정을 고쳤다.
- 상태: 일치 / 문서·코드 차이 / 블로그·코드 차이 / 코드 전용 / 미확인. 한 행에 차이가 있어도 상태는 하나만 적고, 세부는 주장 칸에 쓴다.

## 설계 결정과 PR

한 줄에 하나씩 적는다. 형식은 결정, 번호(유형), 제목, 상태, PR 본문이 주장을 확인하는가 순이다. 유형은 PR인지 이슈인지다. 블로그가 "PR"이라고 부른 것 중 이슈(RFC, 버그 보고, 로드맵)가 있다.

- API server를 EngineCore와 별도 프로세스로 분리: 이슈 #6797 (RFC) "[RFC]: Isolate OpenAI Server Into Separate Process", CLOSED. 확인함. 본문 후속 과제에 증분 detokenizer와 stop string을 API server로 옮기는 항목이 있다.
- API server 분리와 ZMQ 선택: PR #6883 "[ Frontend ] Multiprocessing for OpenAI Server with `zeromq`", 병합. 확인함(Llama-3-8B-Instruct, 1xH100, 10 QPS 조건). 본문 표에서 `grpc`(TPOT 64.15, TTFT 450.05)보다 `zmq + pickle`(57.35, 298.09)이 둘 다 짧다.
- EngineCore 분리와 AsyncLLM: PR #9826 "[V1] `AsyncLLM` Implementation", 병합. 부분 확인. 본문은 EngineCoreClient와 stop string 감지 후 abort를 말한다. "EngineCore를 별도 프로세스로 분리했다"는 문장은 본문에 직접 없다(P1-03은 코드로 확인).
- API server 수와 EngineCore 수를 따로 정함: PR #17546 "[Perf] API-server scaleout with many-to-many server-engine comms", 병합. 확인함. 본문이 `--api-server-count` 추가, DP와 함께 쓸 때 all-to-all ZMQ, DP 크기에 따른 확장과 특히 TTFT 개선을 말한다. 본문 벤치마크 조건은 2xA100, llama-3.2-1B, share-gpt, request rate 120 req/s다. 블로그는 수치 없이 방향만 적는다.
- 엔진보다 먼저 포트 bind: 이슈 #8204 "[Bug]: [Errno 98] error while attempting to bind on address ('0.0.0.0', 8000): address already in use", CLOSED. 확인함. 본문은 CI에서 반복된 address in use 실패를 보고한다. 로그상 포트를 잡은 쪽이 엔진 프로세스였고, 작성자는 엔진 준비 뒤에야 bind하는 순서를 문제로 보며 ray나 분산 통신이 쓴 포트일 것이라 추정하고 ray 로그 확인을 요청한다. Ray라고 확정한 문장은 코드 주석(launcher.py:392)뿐이다.
- A100만 max_num_batched_tokens를 작게: PR #17885 "[Perf] Use small max_num_batched_tokens for A100", 병합. 확인함(제목과 본문을 `gh pr view`로 읽음). 본문은 "A100의 성능 회귀"를 고친다고만 쓰고 원인 분석 문장은 없다. 처리량 전후 표: Llama 70B TP=2는 1054.01에서 1438.49(+36%), TP=4는 3053.03에서 2994.03(-2%).
- Uvicorn signal handler를 설치하지 않음: PR #49668 "[graceful shutdown] fix http server start firstly before app signal handler register", 병합. 확인함. 본문이 server.serve의 capture_signals가 앱 handler를 덮어쓰는 race를 설명한다.
- profiling 중 CUDA graph 메모리 반영: PR #30515 "[UX][Startup] Account for CUDA graphs during memory profiling", 병합. 확인함. 본문은 기본 꺼짐이라고 쓴다. v0.32.0에서 기본 켜짐인 것은 코드(envs.py:328)로 확인했다.
- KV cache 크기 자동 설정: PR #6 "Automatically configure KV cache size", 병합(2023-03-12). 확인함. 본문은 OPT memory analyzer를 넣어 KV cache 크기를 자동으로 정한다고 쓴다(P1-24).
- scheduler 비용과 prefill/decode 구분 없는 설계의 배경: 이슈 #8779 "vLLM's V1 Engine Architecture", OPEN. 확인함. 본문에 "Scheduling is not cheap"과 "Prefix-caching as a first-class feature" 문구가 그대로 있다. 이슈에는 효과 수치가 없고, 수치 근거로는 쓰지 않는다.
- async scheduling 도입: PR #19970 "Implement Async Scheduling", 병합. 확인함. 본문이 실험 기능(`--async-scheduling`)이고 NanoFlow 논문과 비슷한 접근이라고 밝힌다.
- async scheduling 기본 켜기: PR #27614 "[Core] Enable async scheduling by default", 병합(2025-12-29). 확인함(제목과 v0.14.0 릴리스 노트). 블로그는 이 PR 번호를 적지 않고 "v0.14.0"만 적었다.
- Model Runner V2 도입: PR #25266 "GPU Model Runner V2", 병합(2025-11-21). 부분 확인. 제목과 v0.12.0 릴리스 노트(Experimental)는 맞다. 본문은 짧아 기본값 전환을 말하지 않는다.
- Model Runner V2를 모든 모델 기본으로: PR #53183 "[Model Runner V2] Use MRV2 for all models by default", 병합(2026-08-27). 확인함. 본문이 일부 ROCm 모델 예외와 MRV1이 남는 기능이 있다고 쓴다. 블로그는 이 번호 대신 #25266을 붙였다.
- Rust frontend 제안: 이슈 #40846 "[RFC]: Rust front-end", OPEN. 확인함. 본문이 `VLLM_USE_RUST_FRONTEND`로 켜는 drop-in 대체품이고 당분간 Python frontend를 대체하지 않는다고 쓴다. 본문의 벤치마크는 vllm 0.19.0, Qwen3-0.6B, DP=4 조건이다.
- Rust frontend 기능 격차: 이슈 #44280 "[Roadmap] Rust Frontend Feature Parity", OPEN. 확인함. 본문이 실험적이고 아직 기능이 완전하지 않다고 쓴다.
- GLM-5.3 계열의 Rust 네이티브 chat 렌더링: PR #62424 "[Rust Frontend] Add native GLM-5.3 / GLM-5.3-Flash chat rendering", 병합(2026-10-30). 확인함. 본문이 `--tokenizer-mode glm5_next`를 명시해야 하는 경우를 말한다. v0.32.0 커밋(2026-10-17)보다 늦어 이 소스에는 없다(P1-49).

## 수업에 쓰지 말 것

- 레시피의 GLM-5.3-Flash 서버 명령(`--tokenizer-mode glm5_next`)을 "v0.32.0에서 그대로 된다"고 말하는 것. 코드에서 지원 목록에 없고 필요한 PR #62424가 v0.32.0 이후다(P1-49). 수업에서 쓰는 이미지가 어느 커밋인지 먼저 확인해야 한다.
- Rust frontend의 이미지/비디오 입력 지원 여부. 레시피 문구와 v0.32.0 소스가 맞지 않아 판단하지 못했다(P1-50).
- "MRV2가 기본이 된 것은 PR #25266" 같은 표현. 기본값 전환은 #53183이고 #25266은 도입이다(P1-41). 또 "모든 모델이 항상 MRV2"도 쓰지 않는다. Triton이 없거나 미지원 기능이면 V1 runner로 돌아간다(P1-40).
- "async scheduling은 항상 켜져 있다". pooling, 일부 speculative 방식, 일부 executor 조합에서는 꺼진다(P1-42). "step_with_batch_queue = async scheduling"도 쓰지 않는다. PP만 써도 batch queue가 켜진다(P1-43).
- "worker 수 = TP x PP"(arch_overview.md:91, ParallelConfig docstring). 코드는 prefill context parallel 크기도 곱한다(P1-08).
- "AsyncLLMEngine 코드는 vllm/engine/async_llm_engine.py"(arch_overview.md). 그 파일은 별칭 한 줄이고 구현은 vllm/v1/engine/async_llm.py다(P1-05).
- "vLLM 서버 경로에는 listen이 없다"와 Uvicorn 버전별 내부 순서(블로그의 Uvicorn 0.52.4 기준 그림). 단일 API server의 listen은 Uvicorn 쪽이고(루트 환경 0.54.0으로 읽음), API server 여럿의 peer_loads 경로는 vLLM이 직접 부른다(P1-12). 수업에서는 "vLLM은 bind까지, listen은 경로에 따라 Uvicorn 또는 NoSignalServer"라고만 말한다.
- "get_max_tokens가 requested, cap, 최솟값 3단계를 한다"는 서술. requested 결정의 일부와 최솟값만 그 함수에 있고, cap은 서빙 객체 생성자에, 서버 기본값 합치기는 get_diff_sampling_param에 있다(P1-32). 그림은 쓰되 함수 경계는 코드에 맞춰 설명한다.
- V0가 제거된 시점이나 PR 번호. 제거 사실(V0 폴더와 VLLM_USE_V1 부재)만 확인했다(P1-46).
- Rust frontend의 성능 수치(처리량 10% 향상, TTFT 3.3배 등). 확인함: 이슈 본문 벤치마크 1이 "Rust achieves 10% higher throughput than default Python and 3.3x lower P50 TTFT"라고 쓰고(559.79 대 509.56 req/s, P50 TTFT 50.51 대 165.95 ms, Python은 asc=4) 조건은 "Qwen3-0.6B, DP=4 on 4x GB200 GPUs, vllm 0.19.0, request_rate=inf, concurrency=1024"다. 본문이 스스로 현실적인 구성이 아니라고 밝힌다. 이 수치는 이 수업의 모델과 구성(GLM-5.3-Flash, TP)에 해당하지 않는다. 인용하려면 조건을 같이 적어야 한다.
- PR #9826 하나만으로 "EngineCore를 별도 프로세스로 분리한 PR"이라고 단정하는 것. 본문에 그 문장이 없다. 구조 사실은 코드(P1-03, P1-18)로 말한다.
- 문서 열에서 "열어보지 않음"으로 적은 docs 파일(openai_compatible_server.md, prefix_caching.md)의 내용. 이 대장은 해당 문서를 근거로 쓰지 않았다.
