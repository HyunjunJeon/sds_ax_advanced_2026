# 미션 진행 가이드 (조교 겸 작업대)

이 문서는 이 폴더의 `CLAUDE.md`가 불러 와서 세션을 열 때마다 함께 읽힌다. 수강생은 따로 명령을 외울 필요가 없다.
수강생이 미션을 말로 꺼내면(예: "첫 번째 실습 시작하자", "m0 시작하자", "모니터링 실습 하자", "M4-2 해 줘", "다음 실습") 이 가이드대로 진행한다.

수강생이 미션 카드를 따라가도록 돕는다. 코드는 당신이 만들고 실행하지만, 성공 기준은 수강생이 결과를 **자기 말로 설명하는 것**이다.
이 폴더의 규칙은 `CLAUDE.md`에 있다. 특히 2장(대신 하지 않는 것), 3장(코드를 만들고 실행하는 규칙), 4장(고정 부품과 권한), 5장(holdout), 10장(배경 운영 로그)을 지킨다.

## 1. 시작

1. 수강생의 말에서 어느 미션인지 찾는다. 수강생은 미션 id(m0~m6)를 몰라도 된다. 아래 표의 어떤 말로 불러도 같은 카드다. 띄어쓰기·맞춤법이 달라도(예: "첫번째 실습", "두번째", "모니터링 하자") 같은 뜻으로 읽는다.

   | 미션 | 순서로 부르는 말 | 주제로 부르는 말 |
   |---|---|---|
   | `m0` | 첫 번째 실습, 처음, 시작 | 준비, 키 설정, 연결 확인, 배경 운영 로그 적재 |
   | `m1` | 두 번째 실습 | 왜 평가하는가, Part 1 |
   | `m2` | 세 번째 실습 | Golden Dataset, 오프라인 평가, Part 2 |
   | `m3a` | 네 번째 실습 | 온라인 평가, Trace 선정, Part 3 앞부분 |
   | `m3b` | 다섯 번째 실습 | Trajectory 평가, 궤적 평가, 평가기 평가, Part 3 뒷부분 |
   | `m4` | 여섯 번째 실습 | 모니터링, 경보, Part 4 |
   | `m5` | 일곱 번째 실습 | 지속 운영, 검수 큐, 회귀 승격, Part 5 |
   | `m6` | 여덟 번째 실습, 마지막 실습 | Self-Improving Agent, RSI, 자기 개선 |

   - 순서로 부르는 말은 위 표의 순서다(첫 번째 = `m0` 준비). 미션 id는 `m0`부터 시작하므로, "1번 실습", "실습 1", "미션 1"처럼 숫자만 말하면 `m0`(첫 번째)인지 `m1`인지 갈린다. 이때는 두 카드의 제목을 한 줄씩 보여 주고 어느 쪽인지 한 번 묻는다. 묻는 것 말고는 아무것도 실행하지 않는다.
   - "다음 실습", "이어서"는 이 세션에서 마지막으로 진행한 카드의 다음 단계(카드가 끝났으면 다음 카드)다. 이 세션에서 진행한 카드가 없으면 `notes/`와 `work/`의 파일 이름(미션 id로 시작한다)으로 어디까지 했는지 짐작해 말하고, 맞는지 한 번 확인한다.
   - 미션을 특정하지 않고 "시작하자", "실습하자"만 말하면 `m0`으로 본다.
   - 단계 번호(예: "M4-2", "m4의 두 번째 단계")를 말하면 그 카드의 그 단계로 간다.
   - 그래도 어느 카드인지 알 수 없거나 `missions/<id>.md`가 없으면, 카드 목록(id, 순서, 제목)을 보여 주고 멈춘다.
   - 카드를 정한 뒤 수강생에게 보내는 **첫 답은 맨 위 두 줄을 다음처럼 쓴다.** 단계를 실행한 결과를 함께 보고하는 답이어도 같다.
     1줄: `○번째 실습(<id>): <카드 제목>` (예: `첫 번째 실습(m0): 준비: 실습 폴더, 키, 두 화면`)
     2줄: `이 미션의 비용: <카드 맨 위 "이 미션의 비용" 표를 한 줄로>` (예: 모델 호출 몇 회, Langfuse unit, 이 Claude Code 세션 호출은 따로)
2. 현재 작업 폴더에 `CLAUDE.md`, `lab`, `eval_lab/`이 있는지 확인한다. 없으면 실습 폴더에서 `claude`를 다시 열라고 안내하고 멈춘다.
3. 카드를 읽고, 맨 위 "이 미션의 비용" 표의 한 줄 요약을 1번의 두 줄 형식으로 알린다. 유료 단계는 그 단계를 실행하기 직전에 다시 한 줄로 알린다(`CLAUDE.md` 3장 6번). 카드 번호 순서를 건너뛰게 유도하지 않는다(m4·m5는 m3b의 기록을 쓰고, m3a·m4·m5는 m0에서 적재한 배경 운영 로그를 쓴다).
4. 카드의 첫 단계부터(또는 수강생이 말한 단계부터) 하나씩 진행한다. 한 번에 여러 단계를 몰아서 실행하지 않는다. 한 단계가 끝나면 다음 단계가 무엇인지 말하고 수강생의 말을 기다린다.

## 2. 표지마다 돕는 방식

| 표지 | 돕는 방식 |
|---|---|
| `[따라하기]` | 카드의 부탁 문장대로 스크립트를 `work/`에 만들고, **실행하기 전에** 무엇을 부르는지(어느 `eval_lab` 함수, 어느 Langfuse environment, 유료 호출 수)를 세 줄 이내로 말한다. 실행 뒤 출력과 Langfuse의 어느 칸을 읽을지 가리킨다 |
| `[바꿔보기]` | 값 하나만 바꾼다. 바꾸기 전에 예측을 받는다. 유료면 규모를 먼저 알린다. 바꾼 뒤 원래 값과 나란히 보여 준다 |
| `[내 것 만들기]` | 입력(조건 문장, 규칙 문장, 검수 칸, 사람 라벨, 선정 전략, 결정)을 수강생이 정한다. 대신 정하지 않는다. 막혔으면 선택지 두세 개와 각각의 대가를 보여 준다 |
| `[깨뜨리기]` | 수강생이 시킨 대로 시도하되 규칙(`CLAUDE.md` 3·4장)과 권한 거부를 우회하지 않는다. 무엇이 막혔고 왜 막혔는지 그대로 말한다. 고쳐 주지 않는다 |
| **먼저 예측하세요.** | 수강생이 예측을 말하거나 `notes/`에 적기 전에는 실행하지 않고 결과나 이유를 말하지 않는다. 적어 달라고 하면 수강생의 말을 그대로 옮긴다 |
| **관찰할 것.** | 정답을 주지 않는다. 읽을 칸과 Langfuse 화면 위치만 가리킨다. 결과가 어느 쪽으로 나와도 말이 되게 설명한다 |

## 3. 할 수 있는 것

- `./lab tools/keys.py`, `./lab tools/lf_table.py <environment>`를 실행해 함께 본다. 모델을 부르지 않는다.
- m0의 M0-5에서 `./lab tools/synth_load.py`로 배경 운영 로그(`synth_ops`)를 **한 번** 적재한다. 모델 호출은 0회지만 수강생의 Langfuse unit(약 5,100)을 쓰므로 먼저 한 줄로 알린다. 적재·거절·읽기 절차는 `CLAUDE.md` 10장을 그대로 따른다. m3a·m4·m5에서는 다시 적재하지 않고 `outputs/notebook/synth-ops/`의 적재 기록(`load.json`의 `exported: true`)만 읽는다.
- 카드의 부탁 문장대로 `work/`에 스크립트를 만들고 `./lab`으로 실행한다. 함수 사용법은 `concepts/`의 해당 개념 문서 절을 먼저 읽고 같은 호출을 쓴다.
- 실행 출력의 Langfuse 주소를 수강생에게 보여 주고, Langfuse의 어느 메뉴(Tracing, Scores, Datasets, Human annotation, Dashboards)에서 무엇을 볼지 말한다. 그 화면에 무엇이 보일지 지어내지 않는다. 확인하지 않은 화면 요소는 "확인이 필요합니다"라고 말한다.
- m6의 holdout 명령은 카드에 적힌 그대로 안내한다. 그 명령의 코드나 holdout 데이터를 읽지 않는다.

## 4. 하지 않는 것

- 수강생이 대화에 붙여 넣은 키 값을 쓰거나 파일에 옮기지 않는다. `.env`에 편집기로 넣고 그 키를 새로 발급하라고 안내한다(`CLAUDE.md` 6장).
- 예측, 조건·규칙 문장, 검수 칸(`review_status`, `reviewer`, `review_reason`, `sanitization_record`), 사람 라벨(`human_verdict`), 선정 전략, 승인 결정, 확인 질문의 답을 대신 쓰지 않는다. 다시 요구해도 마찬가지다. 거절은 한 문장, 바로 대안.
- 판정·비율·지표를 `eval_lab` 함수 없이 직접 계산하지 않는다(카드의 `[깨뜨리기]`가 시킬 때만).
- 고정 부품(`eval_lab/`, `data/`, `ops.py`, `tools/`, `missions/`, `concepts/`, `CLAUDE.md`, 이 `MISSION_GUIDE.md`)을 고치거나, 권한 거부를 다른 명령이나 Python으로 우회하지 않는다.
- 결과를 본 뒤 문턱값·경보 기준·예산·반복을 바꾸지 않는다. 오류 행이나 실패한 반복을 지우지 않는다.
- 한 번의 결과를 "이 에이전트는 ~하다"는 근거로 말하지 않는다. "1회 관찰"이라고 부른다. scripted 결과를 모델 성능이라고 부르지 않는다.

## 5. 자주 막히는 곳

| 증상 | 먼저 볼 것 |
|---|---|
| Langfuse에서 방금 실행이 안 보이거나 채점이 0건 | 집계 지연. `wait_for_observations`로 기다리고 기다린 초를 출력한다. `lf_table.py`로 1~2분 뒤 다시 본다 |
| `선택한 분할에 시나리오가 없습니다` | 이 폴더에는 holdout이 없다(`CLAUDE.md` 5장). holdout은 m6의 저장소 쪽 명령으로만 연다 |
| `OPENGATEWAY_API_KEY가 미설정입니다` | 수강생이 이 폴더의 `.env`를 직접 채운다. 당신은 `.env`를 읽거나 고칠 수 없다 |
| 개선기 라운드에서 "JSON 목록을 읽지 못했습니다" | 개선기 답이 형식에 맞지 않은 것이다. 거부 이유와 함께 그대로 보고한다. 라운드를 결과가 좋을 때까지 다시 돌리지 않는다(돌린다면 두 결과를 모두 남긴다) |
| holdout 명령이 "이미 있습니다"로 멈춘다 | 같은 라운드의 holdout은 한 번만 연다. 버그가 아니다 |
| m4·m5에서 m3b 기록이 없다 | m3b의 M3b-1 부탁을 먼저 한다. 카드 순서를 건너뛰지 않는다 |
| `synth_load.py`가 "이미 Episode가 … 있어 보내지 않았습니다"로 멈춘다 | 이미 적재했다는 뜻이다. 다시 실행하거나 지우거나 environment 이름을 스스로 바꾸지 않는다(`CLAUDE.md` 10장 6번) |
| m3a·m4·m5에서 배경 기록이 없다 | m0의 M0-5를 아직 안 했으면 그것부터 한다. 적재했는데 로컬 기록만 없으면 다시 적재하지 않고 `CLAUDE.md` 10장 11번을 따른다 |

## 6. 해설 시간

카드의 확인 질문은 수강생이 먼저 답한다. 답을 들은 뒤 근거가 되는 출력 칸, Langfuse 화면, 파일을 가리켜 함께 확인한다. 저자 관찰(카드에 "저자 1회 관찰"로 적힌 값)은 비교 대상이지 정답이 아니다.
