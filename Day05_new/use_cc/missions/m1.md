# M1. 같은 답, 다른 궤적 (Part 1 · 왜 Agent를 평가하는가 · 40분)

> **핵심 질문: 그럴듯한 답이 왜 업무가 성공했다는 증거가 못 되는가?**
>
> 강의는 `reference/01-Why-Evaluate.ipynb` 1~4절의 개념(답변·결과·과정, 같은 답 다른 궤적, 비결정성, 낮은 점수와 평가 불능)을 설명합니다.
> 이 카드는 그 개념을 **Langfuse 화면에서 눈으로 확인**하는 미션입니다. 코드는 Claude Code가 만듭니다.

## 이 미션의 비용

| 무엇 | 규모 | 누구의 비용 |
|---|---|---|
| 이 Claude Code 세션 | 약 8~20회(리허설 전 추정). 스크립트 만들기·실행·설명마다 든다 | 내 Claude Code 계정 |
| 에이전트 모델 | M1-1~M1-4는 0회(scripted). M1-5만 Episode 1개, 최대 12회 | `OPENGATEWAY_API_KEY` |
| Langfuse | Episode 약 3~25개 기록 | 내 Langfuse 프로젝트 |

Langfuse environment는 `cc_m1`입니다.

## M1-1. 먼저 예측하세요 (4분)

강사가 보여 준 "정상 실행"과 "**정책 확인 전에 취소를 먼저 시작해 보는** 실행"(`write_before_approval` 실수를 넣은 scripted 드라이버)을 같은 사례(`normal`)에 돌립니다. `notes/m1.md`에 적습니다.

1. 두 실행의 **최종 답변**은 같을까요?
2. 두 실행의 **마지막 업무 상태**(주문 상태, 환불 금액, 재고)는 같을까요?
3. 오프라인 평가기(기대 상태와 비교, `evaluators.evaluate`)는 두 실행을 같게 볼까요? 다르게 본다면 어느 검사 하나가 갈릴까요?
4. 궤적 규칙(`trajectory_rules.evaluate_trajectory`)은 어느 도구 호출을 첫 위반으로 가리킬까요?

## M1-2. `[따라하기]` Claude Code에게 두 실행을 부탁한다 (6분)

Claude Code에게 이렇게 부탁합니다(문장은 바꿔도 됩니다).

> dev 카드 `normal`을 scripted로 두 번 실행하는 `work/m1_pair.py`를 만들어 줘. 한 번은 기본 드라이버(version `driver-default`), 한 번은 `make_mistake_driver({"write_before_approval": 1.0}, seed=0)`(version `driver-write-before-approval`)로. 둘 다 Langfuse environment `cc_m1`에 남기고, 응답·최종 상태·`evaluate` 검사별 상태·궤적 판정·첫 치명 사건·Langfuse 주소를 표로 보여 줘. `reference/01-Why-Evaluate.ipynb` 2절과 같은 호출을 써.

Claude Code가 만든 스크립트를 실행하기 전에 **무엇을 부르는지 한 번 읽습니다.** 판정 함수가 `eval_lab`의 것인지(직접 다시 짠 것이 아닌지) 확인합니다.

**관찰할 것.** 출력 표의 `policy` 칸과 궤적 판정의 첫 치명 사건(단계 번호와 도구). 예측 1~4와 비교합니다.

## M1-3. `[따라하기]` Langfuse에서 두 trace를 나란히 본다 (6분)

출력의 Langfuse 주소 두 개를 엽니다. 또는 Tracing 화면에서 environment `cc_m1`, Is Root Observation `True`로 거른 뒤 version 칸으로 구별합니다.

**관찰할 것.**

- 왼쪽 **Tree**의 서비스 호출 순서: `driver-write-before-approval` 쪽에서 `service.begin_cancellation`이 `service.check_cancel_policy`보다 **위**에 있는지. 서비스 호출을 하나 눌러 오른쪽 **Metadata**의 `step` 값으로 순서를 확인합니다.
- 두 trace의 root **Preview → Output**의 `response`와 `final_state`가 같은지.
- **Timeline** 탭: scripted 실행은 0.01초 안에 끝납니다. 실제 모델 실행(M1-5)과 비교할 기준입니다.

## M1-4. `[바꿔보기]` 실수 확률과 반복 (8분)

**먼저 예측하세요.** `write_before_approval` 확률을 0.3으로 낮추고 같은 사례를 20번 돌리면, 20번 중 몇 번이 궤적 FAIL일까요? pass@k와 pass^k는 어떻게 다를까요?

Claude Code에게 부탁합니다.

> `work/m1_repeat.py`: 실수 확률 0.3으로 `normal`을 seed만 바꿔 20번 scripted 실행하고(Langfuse에는 남기지 마), 궤적 판정 분포와 `reference/01-Why-Evaluate.ipynb` 3절의 pass@k·pass^k를 같은 함수로 계산해 줘.

**관찰할 것.** 판정 분포에 PASS·FAIL 말고 다른 상태(INCOMPLETE 등)가 있는지, pass@k와 pass^k가 k에 따라 어느 쪽으로 움직이는지. 이 숫자는 **scripted 실행이 만든 모의 결과**이지 모델 성능이 아닙니다.

## M1-5. `[따라하기]` 실제 모델 Episode 하나 (6분, 유료)

비용: 에이전트 모델 최대 12회. 실행 직전에 Claude Code가 `announce` 한 줄을 출력하는지 봅니다.

> `work/m1_live.py`: `normal` 카드를 `mode="live"`, `make_agent_model`로 한 번 실행해 Langfuse `cc_m1`(version `agent-v1`)에 남기고, 궤적 판정과 Langfuse 주소를 보여 줘.

**관찰할 것.** Langfuse의 이 trace는 scripted trace와 무엇이 다른가요? Tree에 모델 호출(`anthropic.messages.create` 등)이 서비스 호출 사이에 끼어 있는지, Timeline에서 시간이 어디에 쓰였는지, 모델이 `check_cancel_policy`를 언제 불렀는지. **이 결과는 1회 관찰입니다.** 옆 사람과 도구 순서가 다르면 그것이 비교할 거리입니다.

## M1-6. `[깨뜨리기]` Claude Code가 직접 계산한 통과율 (5분)

Claude Code에게 일부러 이렇게 부탁합니다(이 카드가 직접 계산을 시키는 유일한 곳입니다).

> M1-4의 20번 결과에서 "통과율"을 eval_lab 함수 없이 네가 직접 계산해 줘.

**관찰할 것.** Claude Code의 코드가 PASS·FAIL이 아닌 상태(INCOMPLETE, NO_EVIDENCE 등)와 `None`을 **분모에 넣었는지 뺐는지.** `reference/01-Why-Evaluate.ipynb` 4절의 "평가 불능을 어떻게 세느냐에 따라 숫자가 바뀐다"와 비교합니다. 이 카드 밖에서는 Claude Code가 판정·비율을 직접 계산하지 않게 되어 있습니다(`CLAUDE.md` 3장 2번). 왜 그런 규칙을 두었는지가 확인 질문 3입니다.
