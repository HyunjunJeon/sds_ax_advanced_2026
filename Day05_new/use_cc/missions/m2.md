# M2. 무엇을 성공으로 볼지 고정한다 (Part 2 · 오프라인 평가와 Golden Dataset · 60분)

> **핵심 질문: 정답이 있는 오프라인 평가에서, "정답"은 누가 어떻게 고정하는가?**
>
> 강의는 `reference/02-Offline-Golden-Dataset.ipynb` 0~7절(Scenario 계약, 사례를 얻는 세 경로, 문서 기반 후보 → 검수, 최소쌍과 커버리지, 검수·동결·dev/holdout, 실험 실행, 판정자 넷)을 설명합니다.
> 이 미션에서 Claude Code는 **후보를 쓰고 실험을 돌립니다.** 후보를 **승인하는 것은 나**입니다.

## M2-2. `[내 것 만들기]` 정책의 빈칸 하나로 후보 카드 쓰기 (12분)

`data/order_policy.md`의 조항(P1~P4)을 읽고, dev 카드 9장(`data/scenarios.json`)이 **시험하지 않는 조건 하나**를 내가 고릅니다. 고른 조항과 조건을 `notes/m2.md`에 한 줄로 적습니다. Claude Code가 대신 고르지 않습니다.

그다음 Claude Code에게 부탁합니다.

> 내가 고른 조건은 "(내 문장)"이야. `reference/02-Offline-Golden-Dataset.ipynb` 1절의 Scenario 계약과 3절의 `draft_cases`처럼, 이 조건을 시험하는 후보 카드 한 장을 `work/m2_candidate.json`에 써 줘. 근거 문장(`source`)은 정책 원문에서 그대로 인용하고, `review_status`는 `pending`, `reviewer`와 `review_reason`은 비워 둬. 기존 dev 카드와 의미가 겹치는지도 해보기 2의 방법(`fingerprint`)으로 확인해 줘.

**관찰할 것.** 후보의 `expected_output`(기대 최종 상태, 금지 도구, 응답 유형)이 정책 원문 어느 문장에서 왔는지. 원문에 없는 내용이 들어갔다면 그것은 Claude Code의 **추측**입니다.

## M2-3. `[깨뜨리기]` 검수 없이 쓰려고 한다 → `[내 것 만들기]` 내가 검수한다 (10분)

먼저 Claude Code에게: "이 후보를 dev 카드에 더해 동결을 시도해 줘. 노트북 02의 9단계·13단계와 같은 함수로." (실습 폴더의 `data/`는 고정 부품이라 수정이 막혀 있으므로, `work/`에 사본을 만들어 시도합니다.)

**관찰할 것.** 어디서 어떤 메시지로 막혔는지(예측 1과 비교).

그다음 **내가** 후보를 검수합니다. `work/m2_candidate.json`을 편집기로 열어 `review_status`(`approved` 또는 `rejected`), `reviewer`(내 이름), `review_reason`(근거 한 문장)을 채웁니다. Claude Code에게 이 칸을 채워 달라고 하면 거절합니다(검수는 담당자의 판단입니다). 다시 동결을 시도하게 하고 결과를 봅니다.

## M2-4. `[따라하기]` 동결한 dev 사례로 실험한다 (12분, 유료)

비용: 에이전트 모델 최대 72회.

> `reference/02-Offline-Golden-Dataset.ipynb` 6절(16~19단계)처럼, 동결한 dev 사례 3장(노트북 13단계와 같은 `normal`, `payment-down`, `missing-id`)을 해시가 들어간 이름의 Langfuse Dataset으로 적재하고, 각 2회 실제 모델로 실행해서 trace를 Dataset 항목에 run 이름으로 연결하고, Code 판정을 점수로 붙여 줘. environment는 `cc_m2`, `work/m2_experiment.py`로.

**관찰할 것 (Langfuse).**

- 왼쪽 메뉴 **Datasets** → 이번 Dataset → 항목 3개와 **run** 하나. run을 열면 항목마다 trace 두 개가 연결되어 있는지.
- trace를 열어 **Scores** 탭에 Code 판정 점수가 붙었는지.
- 같은 항목의 두 실행이 같은 판정인지(다르면 그것이 비결정성이다).

## M2-5. `[내 것 만들기]` 사람 라벨을 먼저, 그다음 Jev·Judge (12분, 유료)

M2-4의 Episode 중 응답이 있는 것 몇 개를 Langfuse에서 읽고, **내가 먼저** 응답 문장이 기록과 맞는지(PASS/FAIL)를 `notes/m2.md`에 적습니다.
그다음 Claude Code에게 부탁합니다.

> `reference/02-Offline-Golden-Dataset.ipynb` 7.2절 21~23단계처럼, M2-4의 Episode를 cascade(Jev 먼저, 불확실하면 Judge)로 의미 판정하고, `notes/m2.md`의 내 라벨과 나란히 놓아 줘. 내 라벨은 고치지 마.

비용: Jev 최대 6회, Judge(xhigh) 최대 18회.

**관찰할 것.** Jev 확률이 미조정 문턱값 0.2~0.8 안이라 Judge로 넘어간 질문의 비율, 사람 라벨과 다른 판정이 나온 질문. 그 차이가 **누가 틀린 것인지**는 아직 모릅니다. 라벨이 한쪽 값뿐이면 `insufficient_coverage`가 나오는 이유도 확인합니다(노트북 24단계).
