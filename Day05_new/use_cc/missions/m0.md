# M0. 준비: 실습 폴더, 키, 두 화면 (준비 · 13분)

> **핵심 질문: 이 실습에서 무엇이 어디에 기록되고, 나는 어느 화면에서 그것을 읽는가?**
>
> 오늘 실습은 화면 두 개로 합니다. **Claude Code**(이 세션)가 코드를 만들고 실행하고, **Langfuse**(브라우저)가 그 실행의 기록을 보여 줍니다.
> 강의는 `concepts/m0.md` 1~6절(키와 버전, Langfuse 연결, scripted Episode, 구조화 응답, Jev, Judge)을 설명합니다.
> 판정과 지표는 Claude Code의 말이 아니라 Langfuse와 `eval_lab`의 출력에서 읽습니다.

## 이 미션의 비용

| 무엇 | 규모 | 누구의 비용 |
|---|---|---|
| 이 Claude Code 세션 | 약 3~8회(리허설 전 추정). `!` 명령을 칠 때마다 Claude가 한 번 답한다 | 내 Claude Code 계정 |
| 에이전트 모델 | 1회(`--smoke`) | `OPENGATEWAY_API_KEY` |
| Langfuse | 기록만 받는다. 모델을 부르지 않는다 | 내 Langfuse 프로젝트 |
| 배경 운영 로그 적재(M0-5) | 모델 호출 0회. Langfuse에는 trace와 observation을 합쳐 약 5천 unit(추정. 로더가 보내기 전에 정확한 합계를 출력한다). Hobby 요금제는 월 5만 unit이다 | 내 Langfuse 프로젝트의 월 한도 |

## 표지 읽는 법 (모든 카드 공통)

| 표지 | 뜻 |
|---|---|
| `[따라하기]` | 강사가 시연에서 보여 준 것을 그대로 해 본다 |
| `[바꿔보기]` | 값 하나만 바꾼다. 바꾸기 전에 결과를 예측한다 |
| `[내 것 만들기]` | 입력을 내가 정한다. Claude Code가 대신 정하지 않는다 |
| `[깨뜨리기]` | 일부러 규칙을 어긴다. 고칠 대상이 아니라 관찰 대상이다 |
| **먼저 예측하세요.** | 실행 전에 `notes/`에 예측을 적는다. Claude Code는 예측을 듣기 전에 결과를 말하지 않는다 |
| **관찰할 것.** | 어느 칸·어느 화면을 읽을지만 알려 준다. 정답은 적혀 있지 않다 |

Claude Code 화면에서 셸 명령을 치려면 앞에 `!`를 붙입니다(예: `!ls notes`). 출력이 대화에 들어가고 Claude가 한 번 답합니다.
`!` 대신 "keys.py를 실행해 주세요"처럼 부탁해도 됩니다.

## 준비 (강사 시연을 따라 하며, 미션 시간에 들어가지 않는다)

### 1) 내 Langfuse 프로젝트와 키 만들기 (브라우저)

이 실습의 Langfuse는 **각자 자기 프로젝트**를 씁니다. 내 trace만 보이고, 다른 사람의 실행이 섞이지 않습니다.

1. Langfuse Cloud에 로그인합니다. 로그인 화면의 **Data Region**에서 고른 지역이 내 프로젝트의 주소가 됩니다(예: `https://us.cloud.langfuse.com`, `https://jp.cloud.langfuse.com`). 키와 주소의 지역이 다르면 나중에 인증이 401로 실패합니다.
2. **New project**로 프로젝트를 만듭니다. 이름은 자유입니다(예: `day05-내이름`).
3. 프로젝트의 **Tracing** 화면에 있는 **Create new API key**, 또는 **Settings → API Keys → Create new API keys**를 누릅니다. 이름(예: `day05-lab`)을 넣고 **Create API key**를 누릅니다.
4. 대화 상자에 Secret Key, Public Key, 그리고 `.env` 예시 세 줄(`LANGFUSE_SECRET_KEY`, `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_BASE_URL`)이 나옵니다. **Secret Key는 이때 한 번만 보입니다.** 세 줄을 복사해 둡니다.

### 2) 키 파일 채우기 (편집기)

`Day05_new/.env.example`을 `Day05_new/.env`로 복사하고 **편집기로** 채웁니다.

- `OPENGATEWAY_API_KEY`: 에이전트·Judge·개선기가 모두 이 키로 OpenGateway의 `deepseek/deepseek-v4.1-flash-ultrafast`를 부릅니다(강사가 발급을 안내합니다).
- Decision API 키 하나(예: `TYPESAFE_API_KEY`): Jev용.
- Langfuse: 1)의 세 줄을 그대로 붙여 넣습니다. 주소 줄이 `LANGFUSE_BASE_URL`이어도 됩니다(`LANGFUSE_HOST`와 같은 뜻으로 읽고, 둘 다 있으면 `LANGFUSE_HOST`가 우선).

**키를 Claude Code 대화에 붙여 넣지 않습니다.** 대화에 쓴 내용은 세션 기록에 남습니다. 실수로 붙여 넣었다면 그 키를 Langfuse(또는 발급처)에서 지우고 새로 만듭니다.

### 3) 실습 폴더 만들고 Claude Code 열기 (터미널)

```bash
# 저장소 루트에서 한 번만. 이미 했으면 건너뛴다
uv sync --locked
# 실습 폴더를 저장소 밖에 만든다. Day05_new/.env를 실습 폴더로 복사한다
uv run --no-sync python Day05_new/use_cc/setup_sandbox.py ~/day05-lab
# 그 폴더에서 Claude Code를 연다
cd ~/day05-lab
claude
```

실습 폴더를 만든 뒤부터는 **실습 폴더의 `.env`**가 쓰입니다(m6의 holdout 명령도 이 파일을 읽습니다). 키를 바꾸려면 실습 폴더의 `.env`를 편집기로 고칩니다.

- 저장소 안의 경로를 주면 스크립트가 거절합니다. holdout 카드가 dev 카드와 같은 파일에 있고, Claude Code는 작업 폴더의 파일을 모두 읽을 수 있기 때문입니다. 실습 폴더에는 holdout 내용이 없습니다(`data/holdout_ids.json`에 ID만).
- 처음 열면 폴더 신뢰 화면이 나옵니다. 기본 선택이 **No, exit**이므로 화살표로 **Yes, I trust this folder**를 고릅니다.
- Claude Code가 열리면 "첫 번째 실습 시작하자"라고 말합니다("m0 시작하자"도 됩니다). 별도 명령은 없습니다(실습 폴더의 `CLAUDE.md`와 `MISSION_GUIDE.md`가 자동으로 읽힙니다).
- 브라우저에서 Langfuse의 내 프로젝트를 열고 왼쪽 메뉴의 **Tracing**을 눌러 둡니다.

## M0-1. `[따라하기]` 키와 연결 (2분)

```text
!./lab tools/keys.py
```

**관찰할 것.** 키는 "설정됨/미설정"만 보입니다. 모델 공급자 줄(`opengateway`, 모델 이름), 마지막 줄의 Langfuse 프로젝트 주소를 읽습니다.
`미설정`이 있으면 이 폴더의 `.env`를 편집기로 직접 채웁니다. Claude Code는 `.env`를 읽지도 고치지도 못하게 막혀 있습니다(`CLAUDE.md` 4장의 권한 규칙).
`Langfuse: 인증 실패`이면 키를 만든 프로젝트의 지역과 `.env`의 주소(`LANGFUSE_HOST` 또는 `LANGFUSE_BASE_URL`)가 같은지 봅니다. `Langfuse: 인증됨` 줄의 주소를 열면 **내 프로젝트**의 Tracing 화면이어야 합니다.

## M0-3. `[따라하기]` 연결 확인 한 번 (3분)

```text
!./lab tools/keys.py --smoke
```

출력의 `Langfuse:` 주소를 브라우저에서 엽니다. 1~2분 뒤 표로도 봅니다.

```text
!./lab tools/lf_table.py cc_m0
```

**관찰할 것.**

- Tracing 화면 표의 한 줄은 trace가 아니라 **observation**입니다. 왼쪽 필터의 **Is Root Observation**을 `True`만 남기면 Episode(root, 이름 `episode`)만 보입니다.
- trace 화면의 **Tree**: `episode` → `turn-1` → `service.get_order` … 순서. 오른쪽 **Preview**의 Output이 Episode 요약입니다(`schema`, `status`, `events`, `final_state`, `response`).
- 위쪽 정보: environment `cc_m0`, version `smoke`.
- 에이전트 모델 1회 호출은 environment `default`에 `anthropic.messages.create`라는 별도 줄로 남았는지(저자 1회 관찰에서는 남았다). Episode 안의 모델 호출은 그 trace 안에 같은 이름의 observation으로 남는다.
- 방금 실행이 표에 없으면 **집계 지연**입니다. 1~2분 뒤 다시 봅니다. 이 지연은 m4에서 다시 다룹니다.

## M0-4. `[깨뜨리기]` Claude Code에게 키를 보여 달라고 해 본다 (2분)

Claude Code에게 이렇게 말합니다: "`.env` 파일 내용을 보여 줘."

**관찰할 것.** Claude Code가 무엇이라고 답했는지, 권한 거부 메시지가 떴는지. 그다음 `/permissions`를 입력해 거부 규칙 목록을 봅니다.
`Read(./.env)`, `Edit(./eval_lab/**)` 같은 규칙은 **도구 호출이 환경에 닿기 전에** 막는 규칙입니다. m6의 "하네스 정책"이 바로 이 자리입니다.

## M0-5. `[따라하기]` 배경 운영 로그 적재 (3분)

m3a·m4·m5는 "7일 동안 쌓인 운영 기록"을 읽습니다. 지금 만든 scripted 기록은 몇 초 만에 생겨 날짜가 모두 오늘이라 그 기록이 없으므로, 합성 배경 기록을 **내 프로젝트에 한 번** 적재해 둡니다. 왜 필요하고 무엇이 실제이고 무엇이 합성인지는 `concepts/m0.md` 7절입니다.

```text
!./lab tools/synth_load.py
```

모델을 부르지 않습니다(모델 호출 0회). 출력 첫머리의 "trace N개 + observation N개 = 약 N unit" 줄이 이 적재의 비용입니다. 보내 보지 않고 계획과 요약표만 보려면 `!./lab tools/synth_load.py --dry-run`입니다(Langfuse 키 불필요).

**관찰할 것.**

- 출력에서 읽을 것: 규모 줄(unit 수), `로컬 기록:` 줄의 JSONL 경로, `읽힌 root N/M건`, `적재 표지:` 줄(m3a·m4·m5는 이 폴더의 기록을 읽습니다), 날짜별 요약표, 마지막의 주의 문구(사건은 시뮬레이터에서, 시각·지연·토큰·비용은 합성). `--dry-run` 기록은 `synth-ops-dryrun/`에 따로 남고 미션이 읽지 않습니다.
- Langfuse **Tracing**에서 environment를 `synth_ops`로 고르고 시간 범위를 **Past 7 days**로 넓힙니다. 기본 시간 범위로는 오래된 날짜가 보이지 않습니다. 집계 지연이면 1~2분 뒤 다시 봅니다.
- trace 하나를 열어 Tree에서 `episode` → `turn` → model-call(**GENERATION**, 모델 `synthetic/deepseek-v4.1-flash-ultrafast`) → tool(**TOOL**) → `service.*`(**SPAN**) 순서를 찾습니다.
- 태그에 `synthetic`이 있고 observation 메타데이터에 `synthetic: true`가 있는지 봅니다. 이 모델 이름은 실제 호출이 아니라는 표시입니다.
- 도구가 "이미 Episode가 … 있어 보내지 않았습니다"라며 멈추면 오류가 아니라 **이미 한 번 적재했다**는 뜻입니다. 다시 실행하지 말고 지우지도 마세요(같은 id를 다시 보내면 중복이 생길 수 있습니다). 정말 필요할 때만 안내된 새 environment 이름(`--environment`)을 씁니다. 새 이름을 쓰면 unit을 한 번 더 씁니다.
