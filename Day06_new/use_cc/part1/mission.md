# M1. 에이전트에게 R6를 맡기고 그 기록을 SDLC 위에 놓는다 (Part 1 · 미션 18분)

> **핵심 질문: 채팅으로 묻는 것과 에이전트에게 맡기는 것은 무엇이 다르고, 맡긴 일의 각 행동은 SDLC의 어느 단계인가?**
>
> 먼저 읽을 곳: `part1/concept.md` (1절 채팅과 에이전트, 5절 AI SDLC 여섯 단계).
> 이 미션이 끝나면 `notes/MY_AI_SDLC.md`의 §1a(실험 기록의 단계 배치)와 §1b(내 최근 작업)가 채워진다.

터미널은 둘이다. **터미널 1**은 `Day06_new/use_cc`의 조교 세션이고 셸 명령 앞에 `!`를 붙인다. **터미널 2**는 실험 폴더에서 여는 실험 대상 세션이다.

## 이 미션의 비용

실험 대상 세션의 값은 **저자 실측 1회 (2026-11-06, Sonnet 5.5, 비대화형)** 이다. 한 번 잰 값이라 범위가 아니고 모델·버전·실행마다 달라진다. 조교 세션의 차례 수는 **예고 (저자 실측 전)** 이다.

| 무엇 | 규모 | 누구의 비용 |
|---|---|---|
| 터미널 1의 조교 세션 (준비와 M1-3~M1-4의 질문과 읽기) | 차례 약 5~10회 (예고 (저자 실측 전)) | 내 Claude Code 계정 |
| M1-2 터미널 2, 실험 폴더 하나 | 모델 호출 6회, 약 0.11달러 (저자 실측 1회, 2026-11-06, Sonnet 5.5, 비대화형) | 내 Claude Code 계정 |
| `/context all`, `/usage` | 모델 호출 여부를 저자가 확인하지 않았다 (확인 필요) | 내 Claude Code 계정 |
| `setup_sandbox.py`, `show_session.py`, `git` | 모델을 부르지 않는다 | 없음 |

실험 대상 세션을 `--permission-mode acceptEdits`로 여는 이유: 시작 모드는 `--permission-mode`로 정하고(C10), 이 모드는 파일 편집과 몇 가지 파일 명령만 묻지 않는다(C6). 어느 호출에서 승인 화면이 뜨는지 직접 보는 것이 관찰 대상이다.

## 준비 (10분, 미션 18분에 들어가지 않는다)

모든 Part에서 한 번만 한다.

1. 조교 세션을 연다. 터미널 1에서:

```bash
cd Day06_new/use_cc
claude
```

2. 처음 열면 **외부 가져오기(External imports)를 허용할지** 묻는다. 이 폴더의 CLAUDE.md가 `@MISSION_GUIDE.md`를 불러오고, 상위의 `AGENTS.md`도 불러오기 때문이다. 바깥 경로를 처음 만나면 승인 대화상자가 뜬다(I4). 커서가 처음에 "No, disable external imports"에 있으니 ↓로 **"Yes, allow external imports"** 를 고른 뒤 Enter.

3. 버전을 본다. 이 수업의 사실은 2.1.318 기준이다.

```text
!claude --version
```

버전에 따라 시작 권한 모드가 다르다. v2.1.283 이상은 대화형의 기본이 auto다(C10). 그래서 아래 실험 대상 세션은 모드를 직접 지정해 연다. 내 버전에서 기본이 무엇인지 확인 필요하면 세션을 열어 모드 표시줄을 본다.

4. 산출물 양식을 복사한다.

```text
!mkdir -p notes && cp lab/MY_AI_SDLC.md notes/MY_AI_SDLC.md
```

5. 안내 문서가 실렸는지 본다.

```text
/context all
```

Memory files 목록에서 `MISSION_GUIDE.md`를 찾는다(I7). `MISSION_GUIDE.md: 4.1k tokens`가 별도 한 줄로 나온다(CLAUDE.md 아래 들여쓰기가 아니라 평면). `/memory`에서는 `CLAUDE.md` 아래 `L MISSION_GUIDE.md @-imported`로 보인다. 둘 다 모델을 부르지 않는다. 안 보이면 지침이 실리지 않은 것이니 조교에게 알린다.

6. 조교 세션에서 **"첫 번째 실습 시작"** 이라고 말한다. 조교가 이 카드를 열고 비용 표를 한 줄로 알려 준다.

## M1-1. 먼저 예측하세요 (2분)

`notes/MY_AI_SDLC.md`의 §1a "예측 (M1-1)" 줄에 아래 네 가지를 순서대로 적는다. 곧 에이전트에게 요구사항 R6 하나를 맡긴다. R6는 "종료 시각이 시작 시각과 같거나 앞서면 저장하지 않고 이유를 알린다"이다(`sandbox_template/test_reservation.py`의 `test_R6_invalid_time_rejected`).

- 도구 호출은 모두 몇 번일까?
- 첫 도구 호출은 무엇일까?
- 검사(`python3 -m unittest`)는 몇 번 돌까?
- 승인 화면은 몇 번 뜰까?

조교는 예측을 듣기 전에 결과를 말하지 않는다.

## M1-2. `[따라하기]` R6를 맡긴다 (7분, 유료)

**비용:** 모델 호출 6회, 약 0.11달러 (저자 실측 1회, 2026-11-06, Sonnet 5.5, 비대화형. 범위가 아니므로 내 실행은 다를 수 있다).

조교 세션(터미널 1)에서 실험 폴더를 만든다.

```text
!uv run python setup_sandbox.py ~/day06-p1
```

폴더는 저장소 밖에 만들어지고 커밋 다섯 개가 들어 있다. 이미 있으면 setup이 거절하므로 그 폴더를 직접 지우고 다시 한다.

터미널 2에서 실험 대상 세션을 연다.

```text
cd ~/day06-p1 && claude --permission-mode acceptEdits
```

1. 폴더 신뢰 화면이 뜨면 읽고 수락한다.
2. 아래 요청을 **그대로** 보낸다.

```text
R6를 구현해 줘.
```

3. **첫 1분을 지켜본다.** 어떤 파일을 먼저 읽는지, 무엇을 돌리는지 본다. 엉뚱한 방향으로 가면 Esc로 멈추고 방향을 말해 준다(K3). 두 번 고쳐도 틀리면 `/clear` 뒤 다시 쓴다(I18).
4. 승인 화면이 뜨면 **무엇이 떴는지 적고** 판단해서 선택한다. acceptEdits여도 `git commit`은 묻는다(C6). 그 밖의 Bash 명령도 읽기 전용 목록에 없으면 묻는다(C6).
5. Claude가 끝났다고 하면 `/exit`로 나온다.

**관찰할 것.**
- 처음 읽은 파일과 처음 돌린 명령
- 승인 화면이 뜬 호출 목록
- "끝났다"고 말하기 전에 검사를 돌렸는가

## M1-3. `[내 것 만들기]` 기록을 두 가지 틀에 놓는다 (6분)

조교 세션에서 방금 세션의 기록을 표로 읽는다.

```text
!uv run python tools/show_session.py --latest ~/day06-p1
```

맨 위 줄에 **권한 모드**, 모델 호출 수, 도구 호출 수가 있다. 권한 모드가 `acceptEdits`인지 먼저 확인하고, 호출 수를 M1-1의 예측과 비교한다.

표의 각 줄을 두 틀에 놓아 §1a에 적는다.

| 틀 | 칸 |
|---|---|
| 에이전트 루프 세 단계(S1) | 맥락 모으기 / 행동 / 결과 확인. 문서는 이 단계들이 섞인다고도 적으므로 한 줄이 둘에 걸치면 그렇게 쓴다 |
| SDLC 여섯 단계 | Plan / Design / Build / Test / Deploy / Maintain (`docs/sources/web.md` 1절. 원문은 이를 비선형이라 부른다) |

- 막히면 조교에게 "이 줄은 어느 단계인지 모르겠다"처럼 줄을 짚어 묻는다. 조교는 그 줄의 도구와 결과를 되묻는다. 대신 놓아 주지는 않는다.
- 이 표는 한 세션의 기록이다. 모델이 무엇을 생각했는지가 아니라 어떤 도구를 불렀는지만 보여 준다.

## M1-4. 내 최근 작업 하나를 같은 표에 놓는다 (3분)

최근 AI에게 맡긴 개발 작업 하나를 떠올려 SDLC 여섯 단계에 놓고 §1b에 적는다. 단계마다 **남은 산출물**(파일, 커밋, PR, 문서)과 **대화에만 남은 것**을 구분한다.

- 업무 내용(코드, 고객 정보)을 조교 세션에 붙여 넣지 않는다. 표에는 내 말로 짧게 쓰고 조교에게도 요약만 말한다.
- §1 맨 위 "예측" 줄에 "내 최근 작업에서 산출물이 가장 먼저 빠진 단계는 ___ 일 것이다"를 적고(§1b를 채우기 전에), 다 채운 뒤 맞았는지 한 줄 덧붙인다.

**관찰할 것.**
- 내 작업에서 "남은 산출물"이 처음 비는 행
- R6 세션의 기록과 비교했을 때, 내 작업에는 없던 "결과 확인" 줄이 있는가

## 마치기 전에 확인

- [ ] §1a의 "예측 (M1-1)" 줄에 네 가지 예측(호출 수, 첫 호출, 검사 횟수, 승인 화면 수)을 실행 전에 적었다
- [ ] §1 맨 위 "예측" 줄에 산출물이 가장 먼저 빠질 단계를 적고, 마친 뒤 맞았는지 덧붙였다
- [ ] §1a에 R6 세션 표의 줄들이 루프 세 단계와 SDLC 단계에 놓여 있다
- [ ] 승인 화면이 뜬 호출을 적었다
- [ ] §1b에 내 최근 작업이 여섯 단계에 놓여 있다
