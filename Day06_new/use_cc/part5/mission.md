## M5-3. `[따라하기]` 계획 A: plan mode (6분, 유료)

터미널 2에서 `/plan` 뒤에 M5-1의 의도 문단을 붙여 보낸다.

```text
/plan <M5-1에서 쓴 의도 문단>
```

- plan mode에서는 승인 전에 파일 편집이 막힌다(공식 문서). 계획이 나오면 **승인하지 않는다.** 실행할지 묻는 화면이 나오면 계획을 계속 다듬는 쪽을 고르거나 Esc로 멈춘다.
  (화면의 정확한 선택지 이름은 저자 확인 전이다. 저자는 비대화형으로만 확인했다. 무엇이 나왔는지 조교에게 알려 준다.)
- 저자 실측에서 계획 파일은 `~/.claude/plans/<세 단어로 된 이름>.md`로 새로 생겼다.
- 계획 파일은 `~/.claude/plans/`에 남는다(공식 문서). 터미널 1에서 가장 최근 파일을 실험 폴더로 복사한다.

  ```text
  !mkdir -p ~/day06-p5/plans && cp "$(ls -t ~/.claude/plans/* | head -1)" ~/day06-p5/plans/plan_a.md
  ```

## M5-4. `[따라하기]` 계획 B: 칸을 정해 요청한다 (6분, 유료)

터미널 2에서 `/clear`로 대화를 비우고(Shift+Tab으로 plan mode에서 나와 있는지 확인), 아래 요청을 보낸다. `<의도>` 자리에 M5-1의 문단을 넣는다.

```text
아래 의도를 구현하는 계획을 plans/plan_b.md 파일로 써 줘. 코드와 검사 파일은 고치지 마.
계획을 쓰기 전에 지금 상태를 확인해(검사를 실행해서 어떤 요구사항이 통과·실패하는지).
맨 위에는 조사 결과와 범위 밖을 적고, 작업마다 다음 칸을 넣어:
- 작업 ID와 연결 요구사항(R#)
- 바꿀 파일
- 먼저 실패하는 것을 확인할 검사 이름
- 통과의 뜻: 실행할 명령과 기대 결과
- 멈추고 사람에게 물을 조건
- 실행 주체: 이 세션에서 직접 / 작업마다 새 하위 에이전트
의도: <M5-1의 문단>
```

## M5-5. 비교한다 (5분)

터미널 1에서 두 계획을 연다(조교에게 "두 계획을 나란히 보여 줘"). §5b 표를 **내가** 채운다. 칸마다 있음/없음과 근거 줄.

| 칸 | 계획 A | 계획 B |
|---|---|---|
| 1. 조사: 계획 전에 검사를 실행했나, R3 실패를 적었나 | | |
| 2. 작업마다 요구사항(R#) 연결 | | |
| 3. 바꿀 파일이 정확한가 | | |
| 4. 먼저 실패할 검사 | | |
| 5. 통과의 뜻(명령과 기대 결과) | | |
| 6. 멈출 조건 | | |
| 7. 실행 주체와 사람 확인 지점 | | |

**관찰할 것.**
- 두 계획이 R4를 어떻게 다루나. R4 검사(`test_R4_overlap_rejected`)는 사용자 A와 B를 함께 쓴다. 각 계획은 겹치는 예약을 **누구의 예약에서** 찾나?
- 두 계획은 R3 실패를 발견했나. 발견했다면 이번 의도(R4~R6)의 범위 안으로 가져왔나, 범위 밖으로 두고 사람에게 넘겼나?
- 계획 B는 요청한 칸을 다 채웠나. 채우지 못한 칸이 있다면 그 칸은 누가 정해야 하나?
