# Day04_new: Agent Capability, Tool Interface, MCP, Skill 노트북 과정

노트북을 위에서 아래로 실행하며 배우는 과정입니다. 하나의 사례를 끝까지 끌고 갑니다. 고객이 하고 싶은 일을 인터뷰해 요구사항을 모으는 **MCP 서버**(Tool 7개, 세션 상태 `draft` -> `ready` -> `frozen`)를 만들고, `create_deep_agent`와 `ChatAnthropic`의 `claude-sonnet-5-5`(effort `medium`)로 만든 **Deep Agent**가 그 서버를 부립니다. 병목으로 측정된 곳의 판단(Decision)은 **Jev**(Decision API)에 맡기고, 측정 기록은 **Langfuse**에 남깁니다.

사례 자료는 수업용 가상 데이터입니다. 설계 결정과 사전 등록(측정 전에 정해 둔 판정 규칙)은 `docs/DESIGN.md`에 있습니다.

## 이 과정이 가르치는 것

- Part 1. Advanced Agent Capability 설계 실습
- Part 2. Advanced Tool Interface 실습
- Part 3. MCP Client/Server 기본 구현 실습
- Part 4. Production MCP 심화 실습
- Part 5. Skill + MCP 통합 실습
- 실습: Agent Capability 평가와 Debugging

Part 1은 능력이 지침(Skill), 도구, 실행 제어, 상태로 이루어진다는 것과 판단을 코드 규칙, 판단 모델(Jev), 생성(LLM) 중 어디에 둘지를 봅니다. Part 2는 도구 정의(이름, 설명, 인자 형식, 출력 형식, 힌트)가 모델의 선택을 어떻게 바꾸는지, Part 3은 stdio 서버와 클라이언트가 주고받는 메시지를 봅니다. Part 4는 재시도, 재개, 캐시, 추적, 사용자에게 직접 묻는 MRTR, 판정기가 없을 때 아무것도 기록하지 않는(fail-closed) 동작을 다룹니다. Part 5는 도구를 Skill이 읽힌 뒤에만 공개하면 무엇이 달라지는지를 작은 실측으로 확인합니다. 실습 06은 결정적 scorer로 Tool 선택, Argument Correctness, Trigger Eval과 Quality Eval, 권한 거부, 오류, 재시도, 중복 실행을 가르고, 07은 병목을 찾아 게이트가 실제로 개선하는지 측정합니다.

점수를 매기지 않습니다. 목표는 코드가 돌아가는 것이 아니라 **각 셀이 왜 그 결과를 냈는지 자기 말로 설명하는 것**입니다.

## 설치와 실행

설치는 **저장소 루트에서 한 번**, 실행은 **`Day04_new/`에서** 합니다.

```bash
# 저장소 루트에서 (한 번만)
uv sync --locked

# 이 폴더에서
cd Day04_new
cp .env.example .env      # 복사한 뒤 편집기로 열어 키를 직접 채웁니다
uv run jupyter lab
```

- 이 폴더 안에서 `uv sync`를 실행하지 않습니다. 환경은 루트에 하나만 있고, Day 폴더에서 실행하면 그 과정에 필요 없는 패키지가 지워집니다. 잘못 실행했다면 루트에서 `uv sync --locked`로 복구합니다.
- 이 폴더에는 `pyproject.toml`이 없습니다. `uv run`이 루트 환경을 찾아 씁니다.
- 노트북 커널의 작업 폴더가 `Day04_new/`여야 `import cap_lab`이 됩니다.

## API 키 설정

키 값은 **본인이 직접** `.env`에 채웁니다. 채팅, 로그, 커밋에 키를 남기지 마세요. 키는 이 폴더의 `.env`에서 읽습니다.

| 환경 변수 | 용도 | 쓰는 노트북 | 비용을 내는 주체 |

## 스위치: RUN_EXERCISE와 RUN_OPTIONAL

돈이 드는 해보기는 **그 셀 안의** 스위치가 `False`일 때 실행되지 않습니다. 스위치는 노트북 맨 위 한 곳에 모여 있지 않고, 유료 셀마다 셀 안에서 `RUN_EXERCISE = False` 또는 `RUN_OPTIONAL = False`로 정해져 있으며 같은 셀에서 `if`로 검사합니다. (01만 예외로 셀 2에서 둘을 함께 정의하고, 유료 셀에서는 검사만 합니다.)

- `RUN_EXERCISE = True`: 해보기 중 본인이 직접 바꿔 보는 유료 셀을 켭니다.
- `RUN_OPTIONAL = True`: 규모가 큰 선택 반복 실습을 켭니다. 표에서 호출 수가 큰 줄이 대부분 여기에 있습니다.

켜고 싶은 셀로 가서 먼저 그 셀의 `announce` 출력과 위 표의 규모를 확인하고, 그 셀 안에서 `False`를 `True`로 바꿔 실행합니다. 다른 셀의 스위치는 켜지지 않습니다(01에서는 셀 2의 값을 바꾸면 그 노트북의 해당 셀이 모두 켜집니다). 07의 `RUN_PREFIX`는 Langfuse 프로젝트를 다른 사람과 같이 쓸 때 변형 이름 앞에 붙는 표를 본인 것으로 바꾸는 변수입니다.

## 막혔을 때 먼저 볼 것

1. **키 미설정**: 00의 키 표가 "미설정"이면 `.env`를 엽니다. `.env.example`을 복사했는지, 이름과 `=` 사이에 공백이나 따옴표가 없는지 확인하고 본인이 직접 채웁니다. 키는 `Day04_new/.env`에서만 읽습니다.
2. **`import cap_lab` 실패**: 커널의 작업 폴더가 `Day04_new/`가 아닙니다. 00의 첫 구간이 이것을 확인합니다. `uv run jupyter lab`을 `Day04_new/`에서 다시 시작합니다.
3. **패키지가 없다는 오류**: 이 폴더에서 `uv sync`를 실행했을 수 있습니다. 저장소 루트에서 `uv sync --locked`로 복구합니다.
4. **Langfuse 인증 실패**: 00의 확인 셀이 `fail: <오류 종류>` 또는 `fail: 키 미설정`을 보여 줍니다. 07은 인증이 통과하지 않으면 측정 셀에서 멈춥니다. 07의 병목 읽기와 손으로 만든 기록으로 하는 셀은 그 전까지 계속 풀 수 있습니다. 키를 고친 뒤 07의 인증 셀부터 다시 실행합니다.
5. **`Task exception was never retrieved ... Event loop is closed` 출력**: 02(셀 32)와 05(셀 27)를 실행하면 stderr에 이 블록이 11번쯤 나옵니다. 저자의 실행에서는 실행도 호출도 실패하지 않았고 결과 표에는 영향이 없었습니다. 오류로 오해해 멈추지 마세요.
6. **Decision API 오류**: Jev 연결 확인(00)을 먼저 통과해야 01, 04, 07의 Jev 셀이 돕니다.
